# 博客与视频的关系

**先说结论：博客怎么写由你定，我不设格式。**

结构、长度、语气、有没有小标题、写不写公式——都不限制。
你的博客是给自己复习和回忆用的，不是给我的流水线做接口的。
所以这里没有"必须包含哪些段落"，也没有模板要套。

新建文章的命令只会给你一个空壳：

```bash
python -m manimations new-blog 01-数学基础 01-01 points-and-vectors --title "点与向量"
# 生成：blog/01-数学基础/01-01-points-and-vectors.md
# 内容：只有一行 "# 点与向量"
```

## 只有两件事和写作无关、但工程上要对齐

这两条不涉及你写什么，只涉及文件放哪儿：

1. **一篇一个文件**，放在 `blog/<阶段>-<主题>/` 下。
2. **文件名以讲次编号开头**，例如 `01-01-points-and-vectors.md`。
   编号和 `blog/00-学习路线/README.md` 清单里的 `id` 一致即可。
   视频模块名由它自动推导（`01-01-points-and-vectors` → `points_and_vectors`），
   这样文章、分镜、成片三者能对上，而不用维护一张映射表。

标题用 `#` 写在第一行就行——`dsh index` 靠它填目录，其余它不管。

## 视频怎么来

**转译是我的活，不是你的。**

我读完你的文章，自己决定分几页、每页放什么图、公式怎么出现。
你不需要为了镜头把句子改短，也不需要提前标"这段适合做动画"。

如果某篇里我找不到可视化抓手（比如全是文字感悟、没有具体对象），
我会**直接问你**："这一讲想让人看到什么画面？"
而不是回过头要求你改文章结构。

## 什么内容会让我更好做（建议，不是要求）

纯粹是"有这些我会做得更准"，没有也不影响你写：

- 一个具体的数（`0.83` 比"误差很大"更有用，能直接变成画面上的读数）
- 公式尽量用 `$$ ... $$` 独立成行。**行内 `$...$` 能不能渲染，取决于你用哪个
  编辑器**（VS Code 内置预览、GitHub、Obsidian 的默认行为都不一致）；独立公式块
  是最稳的。单个符号（α、γ、−、→）直接打 Unicode 字符就行，不必套 `$`
- 一处你当时卡住的地方（那通常就是一页动画最好的切入点）
- 一段能跑的代码或一个 API 名（视频会调 `cgviz` 里同名的函数）

但这些都不是条件——你想怎么写就怎么写，缺的部分我来补或来问。
